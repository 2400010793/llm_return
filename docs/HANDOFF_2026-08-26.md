# LLM Return 完整交接文档（2026-08-26）

## 1. 交接摘要

项目已从论文复现框架推进为中国市场文本实证平台，当前包含：

- 新浪财经历史新闻、巨潮资讯公告两套主文本面板；
- 东方财富和雪球的公开可见投资者内容采集原型；
- RoBERTa、BGE-M3、Qwen3-Embedding-8B 三种冻结 embedding；
- prompt 目标 span、正文和全文 pooled 表示；
- 严格时间滚动 PCA 回归、硬/软聚类、UMAP+HDBSCAN、GMM 和预测级融合；
- 日频/O2O 收益、波动率、价差、估值标签和交易成本回测。

当前最关键的未完成任务是四个方向 prompt 的三模型公平比较：

```text
分析股票盈利
分析股票收益
分析股票超额收益
分析股票亏损
```

它只使用 `masked_short`、三个模型的共同新闻、PCA32 和固定参数，比较目标 token 与
真正正文表示。新浪按 6+2+1，巨潮按 3 年历史+1 年测试。构建任务仍在等待调度，
所以“Qwen 是否兼顾共同语义和细粒度差异”目前仍是假设，不是已完成结论。

### 3.2 新浪流程 A：普通 HTTP 历史扩展

适用场景：已经有一批有效历史文章 URL，需要快速、可恢复地扩展正文和相邻文章。

入口：

- `scripts/run_sina_auto_pipeline.py`
- `scripts/crawl_sina_bfs_fast.py`
- `scripts/crawl_sina_dfs.py`，仅作遍历顺序对照
- 公共解析/恢复逻辑：`scripts/sina_http_crawler_common.py`

自动流水线的实际顺序：

```text
root file
  -> depth-3 bounded HTTP graph crawl
  -> 保存 raw HTML / records JSONL / manifest / state
  -> URL + body SHA256 全局去重
  -> 当前 runner 排除 2000 年记录
  -> 去重文章 URL 作为新 roots
  -> depth-5 expansion
  -> 再次 URL + body SHA256 去重
```

关键设计：

- `ThreadPoolExecutor` 有界并发，不为每个 URL 建立无限线程；
- robots 无法确认允许时不继续访问该 host；
- GBK/GB18030 历史页面按 HTTP/meta charset 解码，避免强制 UTF-8 破坏中文；
- 原始 HTML 按 URL 哈希保存，records 逐行落盘；
- state 保存已访问 URL、frontier、参数和 parser 版本，resume 参数不一致会失败；
- 按 URL 和正文哈希去重，不能只按标题去重；
- 股票关联同时参考新浪股票链接、明确股票代码和公司名词典。

当前自动流程默认配置：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `workers` | 20 | HTTP 并发上限，允许 1--50 |
| `pause-seconds` | 1 | 有界批次之间的等待，不是每线程固定 QPS |
| `timeout` | 30 秒 | 单请求超时 |
| stage 1 depth | 3 | 第一轮从人工/浏览器种子扩展 |
| stage 2 depth | 5 | 从去重文章根继续扩展 |
| body length | 120--12000 字符 | 低质量过滤与模型正文上限 |
| `max-seconds` | 默认无 | 默认到 frontier 耗尽；正式跑前应显式给本地时间预算 |

20 workers 只是并发配置，不代表 20 页/秒。底层按最大 `workers*20`、至少 100 的批次
处理，网络、页面响应、robots、解析和批次 pause 都影响实际速度。

本地 PowerShell：

```powershell
$env:PYTHONPATH = "scripts"
python scripts/run_sina_auto_pipeline.py `
  --root-file data/interim/sina_roots.txt `
  --stock-catalog data/stock_universe_csi500_current.csv `
  --output-dir data/interim/sina_auto_v1 `
  --workers 20 --pause-seconds 1 --timeout 30
```

### 3.3 新浪流程 B：浏览器 seed 发现与年度补洞

适用场景：页面依赖渲染、普通 HTTP 找不到历史入口，或某些年份缺少有效根 URL。

入口：

- `scripts/select_sina_historical_seeds_browser.py`
- `scripts/discover_sina_stock_news_seeds.py`
- `scripts/discover_sina_year_roots_from_hotspots.py`
- `scripts/search_sina_historical_seeds_by_keyword.py`
- `scripts/run_sina_annual_expansion.py`

浏览器 selector 支持 `--root`、`--root-file` 和 `--candidate-file`。每页记录来源 URL、
父 URL、depth、发现方式、标题、日期、正文长度、正文哈希、股票匹配和子链接数。seed
不是简单取分数最高的相似文章，而是 farthest-first：优先新股票、新频道路径、新季度、
低标题词重合，再考虑单股票、目标年份和正文长度。默认每只股票每年最多一个 seed。

默认配置：

| runner | 并发 | pause/render | 范围 |
|---|---:|---:|---|
| selector | 8 browser pages | 3s / 500ms | 300 pages，depth 2，20 seeds/year |
| annual expansion | 4 year jobs x 2 pages | 1s / 300ms | 1000 pages/year，depth 5，100 seeds/year |
| hotspot discovery | 20 pages | 0.3s / 500ms | 每 root 最多 100，depth 2 |
| keyword search | 8 pages | 页面内 timeout 30s | 每年最多 100 |

年度 runner 将 roots 按 URL 年份拆开，各年独立队列、独立输出和 manifest。默认理论浏览器
并发上限为 8，而不是对 27 年各开 8 个页面。

### 3.4 新浪应采用哪种方式

**推荐混合方式：浏览器发现、HTTP 扩展。**

- 普通 HTTP 更适合批量正文：速度更高、资源少、原始响应和 resume 更容易审计。
- 浏览器更适合动态入口和缺失年份：覆盖灵活，但渲染开销、失败模式和资源占用更高。
- 不建议用全浏览器替代全部历史正文，也不建议只用一个现代根 URL做普通 BFS。
- 年份均衡要靠多年份 seed 和配额实现，`uniform frontier` 只均匀探索当前图，不等于
  按年份统计抽样。

当前速度事实只有微型探针：

| 探针 | 访问页 | 时间 | 仅供说明 |
|---|---:|---:|---|
| 普通 DFS | 2 | 0.38 秒 | 5.263 visited/s，小样本不代表容量 |
| 浏览器 BFS | 4 | 4.90 秒 | 0.816 visited/s |
| 浏览器 DFS | 4 | 4.77 秒 | 0.839 visited/s |

这些探针没有形成有效全量吞吐估计，浏览器 seed 探针也曾访问 7/32 页但选中 0 条。
报告不能写“当前可稳定达到 X 万条/小时”，直到完成一次带 summary 的本地长跑。

**新浪硬约束：所有联网采集只能在本地机器运行。** 不提交 Slurm，不在集群 CPU/GPU
节点联网抓取。Lustre 只接收本地采集后的 raw HTML、JSONL、state、manifest 和 checksum。

### 3.5 巨潮资讯 CNINFO

巨潮是上市公司法定披露公告来源，不是普通新闻站。当前官方可见页面采集器
`scripts/collect_cninfo_announcements.py`：

1. 通过公开公司披露页解析 `stockCode/orgId`；
2. 在可见日期控件中设置起止日期并查询；
3. 顺序读取公开分页的公告标题、公告日期和详情链接；
4. 打开详情页并下载页面公开链接的 PDF；
5. 保存原始 PDF，使用 `pypdf` 抽取文本；
6. 对下载失败、空 PDF 文本、访问控制和导航失败显式记错，不静默补零；
7. 按公告 URL/document ID 去重，清洗正文并与分类、收益和 O2O 面板对齐。

历史收集审计：

| 指标 | 数值 |
|---|---:|
| 股票 | 816 |
| 2010--2017 股票年 | 6,528/6,528 完成 |
| 完成文件中的原始记录 | 554,451 |
| 最终 2010--2026 面板 | 903,665 |
| 日期 | 2010-01-03 至 2026-07-31 |
| 唯一 `row_index` / `document_id` | 903,665 / 903,665 |
| 文本中位数 / p90 | 1,765 / 11,737 字符 |
| 文本至少 100 字 | 882,610 |

这里的时间覆盖和公告范围必须分开写：同一批 816 只股票整体覆盖 2010--2026；
2010--2017 是全部公告，2018--2026 是重点公告。最终面板中前段清洗后 553,088 行，

#### 巨潮股票范围的准确口径

`collect_cninfo_announcements.py` 接收 `CODE:ORG_ID:NAME`，所以技术上可以爬取任何能够在
巨潮公开公司披露页解析出 `stockCode` 和 `orgId` 的上市公司；816 不是网站允许的上限。
本项目的 816 是 `data/stock_universe_paper_1000.csv` 的 1,000 个候选股票与公告/收益面板
交集后得到的研究范围，其中沪市 64 只、深市 752 只，代码前缀为 `000/001/002/300` 和
`600/601/603/688`，未纳入北交所。2010--2017 按 816 x 8 个股票年逐一审计，6,528/6,528
完成；这不是“全 A 股历史公告已完整下载”。

903,665 行是两个筛选口径清洗和标签对齐后的合并分类面板，不等于历史爬虫下载的 PDF
数量。2010--2017 全部公告的完成文件原始记录为 554,451 条，清洗后 553,088 行；
2018--2026 重点公告为 350,577 行。详情/PDF 下载、文本抽取、URL/document ID 去重、
正文过滤和收益对齐后才形成面板。扩展到全 A 股时，必须先建立包含代码、交易所、
公司名和 orgId 的新目录，分股票年小批量探针，再做缺失审计；不可只修改
`--expected-stocks`。

#### 新浪本地采集的原因和流水线

新浪的本地限制是访问上下文和可复现性约束，不是 CPU 或 embedding 限制。浏览器发现、
历史编码、动态入口、限速和会话状态都在本地完成；集群只接收校验后的 raw HTML、JSONL、
state、manifest、checksum，用于离线清洗和模型任务。禁止在 Slurm CPU/GPU 节点联网抓取，
避免分布式 IP/会话造成访问控制和结果不可复现。

本地流水线为：浏览器按股票/年份/季度/频道差异发现 seed；普通 HTTP depth-3 扩展并解析
标题、日期、正文、股票关联和链接；按 URL 与正文 SHA256 去重；将有效文章作为新 roots 做
depth-5 扩展；对动态入口或年份断档使用年度浏览器 runner 补洞；最后生成稳定 records、
state、manifest 和 checksum，再复制到 Lustre。HTTP 默认 20 workers、1 秒批次 pause、
30 秒 timeout；浏览器 selector 默认 8 pages、3 秒 pause、500ms render wait。20 workers
是并发上限而非吞吐承诺，正式速度必须由本地带 summary 的长跑测量。

入口脚本：`scripts/run_sina_auto_pipeline.py`、`scripts/crawl_sina_bfs_fast.py`、
`scripts/select_sina_historical_seeds_browser.py`、`scripts/run_sina_annual_expansion.py`。
修改解析器或参数后必须使用新的 output-dir/manifest 版本，不能把不同规则的 frontier
state 混用。

### 4.1 清洗合同和行数来源

新浪清洗以源文章为第一层，以股票-文章为第二层。原始 714,555 行中 714,549 行可以进入
解析，最终接受 167,713 篇源文章；同一篇新闻若在清洗后的标题或正文中明确对应多只股票，
会展开为多个股票-文章行，因此最终是 796,553 行、5,466 只股票。公司归属不能只依赖网页
股票链接，必须有明确六位代码或无歧义公司名称证据。模板清洗移除导航、分享、编辑/推广
尾注和现代页面头，过滤无效时间、URL 日期冲突、乱码、指数/行情/专题页及少于 120 字正文。
去重键按 `source_article_id+stock_id`、`url+stock_id`、
`stock_id+cleaned_text_hash` 分层执行。

巨潮清洗先保存详情和 PDF 状态，再抽取正文；页码、HTML、URL、PDF/浏览器样板、替换字符
和异常空白在正文阶段处理。通用合并档输入 913,014 行，按 `stock_id+text_hash` 删除
9,198 行后为 903,816 行；不同股票共享相同文本不会互相去重。**研究和 embedding 的冻结
合同不是该通用档**，而是 2010--2017 全部公告 553,088 行与 2018--2026 重点公告
350,577 行的已审计合并，合计 903,665 行。两套产物相差 151 行，目前只能确定属于版本/
选择合同差异，尚无逐行原因审计；接手者不得猜测原因，也不得无审计替换。

所有最终输入重新生成稳定 `row_index`、唯一 `document_id`、六位股票代码、日期和正文
hash。Embedding 验收必须同时检查行数、顺序、manifest hash 和 shard 行区间，不能只看
目录中是否存在 `.npy`。

### 4.2 日期和收益标签的点时对齐

1. 股票代码先补齐为六位；首位为 5/6 的证券映射 `.SH`，其余映射 `.SZ`。
2. 新浪 `published_at` 按 UTC 解析、转 `Asia/Shanghai` 后保存本地无时区时间；解析失败
   的记录拒绝。巨潮优先使用 `published_at`，无效时退回 `announcement_date`；历史公告
   多为日期级 `00:00+08:00`，不能假装具有盘中分钟精度。
3. `event_center_date` 是公告自然日当日或之后的第一个交易所交易日；`entry_date` 是严格
   晚于公告自然日的第一个交易所交易日。周末和节假日按真实交易日历顺延。
4. `next_day_return` 是 `entry_date` 对应的日收益。主面板对所有记录都使用保守的下一
   交易日口径，不根据盘中发布时间设置收盘 cutoff。
5. `event_return_3d` 复合 center-1、center、center+1 三个交易日，可能包含公告前一天，
   只能作为事件研究/历史标签，不能解释为从公告后可部署的三日远期收益。
6. O2O 从 `entry_date` 开盘到下一个交易日开盘，仅当两个开盘价都存在且通过 IPO/可交易
   检查时保留；按 `(stock_id, entry_date)` many-to-one 合并。
7. 估值用 backward `merge_asof` 取 `available_at <= published_at` 的最近观测。日内指标
   的下一日水平/增量先在 ticker 内显式 `shift(-1)`，再按股票和日期合并。

该规则比“收盘前公告当天可用”更保守，但与巨潮日期精度一致。仓库中若有旧函数文档提到
盘中 cutoff，以当前主分类面板的“严格下一交易日”合同为准。滚动实验中的 scaler、PCA、
聚类器、标签选择和回归模型仍只能在当前历史训练/验证范围拟合。

## 5. 模型介绍、来源与产物合同

### 5.1 中文 RoBERTa

- 模型 ID：`hfl/chinese-roberta-wwm-ext`
- 类型：双向 Transformer encoder，中文 whole-word masking 系列
- hidden size：768
- 本项目最大长度：512 token
- 正文表示：`body_mean`
- 目标表示：`prompt_token_embeddings` 中目标 span 均值
- 中性全量输出还包含：`prompt_mean`、`title_mean`、`body_mean`、
  `title_body_mean`、`full_mean`、`cls` 和对应 max pooling。

双向注意力意味着前置 prompt 可以改变后续正文 token 的表示。因而 token/body 比较既
包含目标 span 的选择，也可能包含 prompt 对正文编码的调制，必须使用同 prompt 的
`body_mean` 配对控制。

### 5.2 BGE-M3

- 模型 ID：`BAAI/bge-m3`
- 类型：双向、多语言 embedding encoder
- hidden size：1024
- 本项目最大长度：1000 token
- 产物类型与 RoBERTa 相同，但模型/tokenizer/output 目录完全分离。

BGE-M3 的四方向 token 因子平均相关高于 RoBERTa，说明 prompt 间表示更平滑。它可能
代表共同语义更强，也可能损失方向词的细节；必须通过样本外多 prompt 融合判断。

### 5.3 Qwen3-Embedding-8B

- 本地 runner ID：Ollama `qwen3-embedding:8b`
- 类型：因果 embedding 模型
- hidden size：4096
- prompt 位置：正文之后
- 正文表示：已有 `article_mean`
- 目标表示：prompt 目标 span 均值，排除末尾句号。

因果注意力下，前面的 `article_mean` 不会受到后置 prompt 的反向影响，这与 RoBERTa/
BGE-M3 不同。公平比较统一算法和新闻交集，但不能声称三者的正文 embedding 有完全相同
的结构含义。

### 5.4 已测性能

| 数据/任务 | 模型和表示 | 方法 | RankIC | 稳定性 |
|---|---|---|---:|---:|
| 新浪 event-3 | RoBERTa+BGE-M3 masked“收益”span | 各 PCA64 后拼接 + Ridge | 0.08945 | 9/9 |
| 新浪 next-day | RoBERTa masked `分析股票收益` prompt mean | Ridge | 0.06044 | 9/9 |
| 新浪 next-day | RoBERTa short“超额收益”span | Ridge | 0.05851 | 9/9 |

| 巨潮 residual O2O | Qwen masked-short PCA32 | Huber SGD, 3+1+1 | 0.02732 | 5/5 |
| 巨潮 strict 2026 | Qwen masked-short PCA32 | Huber SGD | 0.02247 | 单年，CI 跨 0 |

上表混合了不同任务和历史实验，只说明每类模型已有可用实现，不是严格三模型排名。
真正公平比较必须使用同 prompt、同新闻、同标签和同 PCA32 规则。

### 5.5 Embedding 实测用时和估算方法

六个中性 Prompt 的 CPU array 固定为 256 shards、`%256` 最大并发、每 task 8 CPU/
32 GB、24 小时时限。RoBERTa 用 batch 8、最大 512 token；BGE-M3 用 batch 4、最大
1,000 token。一个 task 只加载一次模型，然后编码该 shard 的全部六个 Prompt。

| 数据/模型（基础 job） | 完成状态 | 已完成 task 的中位 / P90 / 最大 `ElapsedRaw` | 首个运行至最后完成 |
|---|---|---:|---:|
| 新浪 RoBERTa（4985394） | 256/256 | 46分50秒 / 3时04分36秒 / 3时32分12秒 | **4时28分17秒，完整** |
| 巨潮 RoBERTa（4985396） | 255/256，shard-225 失败后另补 | 1时11分10秒 / 2时01分47秒 / 4时33分41秒 | 9时16分57秒，基础 array 非完整 |
| 新浪 BGE-M3（4985395） | 189 完成、67 取消；保留 588,049 行 | 5时15分51秒 / 9时07分35秒 / 15时19分15秒 | 15时49分45秒，仅部分任务窗口 |
| 巨潮 BGE-M3（4985397） | 78 完成、178 取消；保留 221,551 行 | 4时36分44秒 / 4时54分07秒 / 6时42分05秒 | 8时28分01秒，仅部分任务窗口 |

这里的 task 用时是 Slurm 已完成 array element 的计算时间，不含排队；墙钟是首个实际开始
到最后一个完成，不是 `sbatch` 提交到完成。BGE 两组因取消而没有全量实测墙钟，不能用
部分窗口冒充完成时间。在健康节点且能获得 256 个并发槽位时，以 P90 并增加至少 20%
I/O/校验余量，BGE-M3 条件预算为新浪约 10--16 小时、巨潮约 5--7 小时；若有效并发为
64，则约需四个 wave。公式为：

```text
compute wall ~= ceil(shards / effective concurrency)
                x representative shard elapsed
                x (1 + I/O and validation buffer)
total turnaround = scheduler queue delay + compute wall
```

Qwen 只有一个可用于容量标定的完整 pooled job：3651805 在一张 RTX 4090 上处理 57,741
行，用时 18,715 秒（5时11分55秒），约 3.085 行/秒，输出单个 4,096 维 pooled 向量。
同吞吐单 pass 线性外推为新浪 71.7 小时、巨潮 81.4 小时；它不包含完整 Prompt token
输出合同，不能乘六后当成正式工期。GGUF token runner、输入长度、缓存和 GPU 并行度必须
另做至少一个完整 shard benchmark。证据和估算边界见
`references/embedding_runtime_audit_20260826.md`。

## 6. Benchmark 实验

### 6.1 论文基线

工作区论文的共同框架是“冻结文本表示 + 简单监督预测器 + 严格滚动样本外 + 组合评价”。
仓库保留以下 benchmark 层级：

1. 非文本控制：过去收益、规模、成交量、波动率；
2. 传统文本：情绪词典、TF-IDF + Ridge、Word2Vec；
3. 整文 embedding：RoBERTa/BGE/Qwen 正文或 pooled 表示；
4. prompt pooled：`prompt_mean/full_mean`；
5. 本项目扩展：精确目标 token、mask、聚类和多模型融合。

当前三模型公平比较不重新运行所有原始基线，而把“同一表示的 PCA32+Ridge”作为每个
token/body/聚类配置的直接 benchmark。这样聚类增量不会混入维度、训练期或新闻池差异。

### 6.2 时间协议

- 新浪：6 年训练 + 2 年验证 + 1 年测试，测试年 2018--2026；
- 巨潮公平比较：固定 3 年历史 + 1 年测试；
- 巨潮既有 Qwen residual：3+1+1，用内层 OOS 预测训练二级模型；
- 标准化、PCA、KMeans、UMAP、HDBSCAN、簇收益、Ridge 和融合器全部只在当前 fold
  允许的历史数据拟合；
- 测试年不能用于选择 PCA 维数、k、temperature、shrinkage 或模型权重。

### 6.3 统一评价

主指标：日均 RankIC、RankIC IR、逐年 RankIC、正 RankIC 年份数。

辅助指标：月度正 IC 比例、日期 block bootstrap 95% CI、OOS R2、方向 Accuracy、
Top20 同新闻池超额、Top20 多空、5bp 单边成本后的 CAGR/Sharpe/最大回撤、因子
Spearman 和 Top20 选股重合。

IC、组合收益和分类准确率回答不同问题，不能互相替换。新闻同池 Top20 超额也不能与
全市场 RetL 直接比较。

## 7. Mask 与 Prompt 扩展

### 7.1 Mask 合同

当前新增实验只用 `masked_short`：

- mask 公司名、公司身份、股票代码、日期和时间；
- 不 mask 盈利、收益、亏损、估值、风险、波动率等目标语义；
- 不生成 long、masked-long 或无意义 padding；
- 保存 mask 前后哈希、tokenizer、input IDs、正文起点、正文可见 token 和截断位置；
- synthetic probe 必须确认公司名/日期无残留，正文预算和 separator 结构稳定。

历史 paired 结果：16 个配置中，mask 对成本后只做多 Sharpe 平均 +0.069，9/16 胜，
年化收益平均 +1.15 个百分点；但 `simple_states` IC 平均 -0.00480，仅 8/16 胜。
正确结论是“mask 控制身份和时间泄漏”，不是“mask 必然提高性能”。

### 7.2 Prompt 合同

方向 prompt：

```text
分析股票盈利
分析股票收益
分析股票超额收益
分析股票亏损
```

中性任务 prompt：

```text
分析股票估值
分析股票确定性
分析股票波动率
分析股票冲击
分析股票流动性
分析股票风险
```

目标 span 只取目标短语的 tokenizer 对应 token，多个 token 取均值，不含“分析股票”、
句号、separator、CLS/EOS。RoBERTa 中文通常按单字切分，但验收仍读取真实 tokenizer
input IDs，不能只按字符数假定。

不同 prompt 长度不使用无意义词补齐。跨 prompt 不比较原始坐标，而比较模型内 centered
cosine、标准化距离和完全样本外因子。正文最大长度、mask、行顺序和截断规则保持一致。

### 7.3 从收益到语义匹配标签

中性 prompt 不应全部预测 next-day return：

- 估值：下一日 PE/PB/PS/EV-EBITDA 的 log 相对偏离；
- 波动率/风险：下一日实现波动率水平、下一日 log 增量、5 日相对 20 日跳升；
- 流动性：下一日买卖价差水平和下一日价差 log 变化；
- 冲击：event return、absolute return、成交量冲击；
- 确定性：absolute return、tail、波动率或预测残差的稳定度。

估值的“高/低”按股票自身历史标准定义：正 PE/PB/PS/EV-EBITDA 取 log，减去过去
252 个交易日、至少 60 日的滞后 log 中位数。不能拿跨股票 PE 绝对值直接判断高估。

## 8. PCA 与聚类：原理和实现

### 8.1 PCA32 + Ridge 主基线

原始 embedding 分别为 768、1024、4096 维，样本和维数的尺度也不同。每个模型、prompt、
表示和 fold 单独在训练期拟合 randomized PCA32，然后对分量做 StandardScaler，最后
Ridge alpha=100。三模型使用相同算法和维数，但不能共享一个 PCA 基底。

PCA 最大化训练数据投影方差：

```text
Z = (X - train_mean) W_32
y_hat = Z beta,  beta = argmin ||y-Z beta||^2 + 100 ||beta||^2
```

这是所有聚类方法的配对基线。当前公平比较不做 raw regression，不运行 PCA64/no-PCA
稳健性扫描，不因测试结果切换维数。

### 8.2 硬 MiniBatchKMeans

原理：在训练期 PCA 空间寻找 k 个质心，使样本到最近质心的平方距离总和最小。每条新闻
获得一个离散簇标签，代表一个粗粒度语义状态。

实现：

```text
train embedding -> train PCA32/scaler -> MiniBatchKMeans(k=6)
-> cluster one-hot / center distances + PCA32 -> Ridge(alpha=100)
```

当前固定 k=6。历史 sweep 使用 k=2/4/6/8/12 和 seeds 17/29/42/71/113；参数只看
验证期 RankIC。硬 KMeans 相对同 PCA Ridge 的 16 个 paired 结果平均 RankIC 增量
-0.00026，仅 6/16 胜，不能写成稳定提升。

### 8.3 软 KMeans + 簇收益收缩

硬标签在簇边界产生跳变。软聚类把样本到每个质心的距离转换成 membership：

```text
w_ik = softmax(-d_ik^2 / (temperature * distance_scale))
mu_k = (sum_{i in k} y_i + shrinkage * global_mean) / (n_k + shrinkage)
score_i = sum_k w_ik * mu_k
```

当前固定 `temperature=0.5`、`shrinkage=500`、k=6。`mu_k` 只能用训练期收益估计；
验证/测试只应用冻结质心、scale 和簇收益。temperature=0 退化为硬分配。

新浪旧实验的方向软聚类最佳为 BGE-M3 short“超额收益”RankIC 0.04439，9/9 年为正；
但最强线性 prompt mean 已到 0.06044。因此软聚类能提取局部分层，不代表普遍超过线性。

### 8.4 UMAP8 + HDBSCAN

UMAP 从 PCA 空间构建近邻图，优化低维表示以保留局部邻域；HDBSCAN 在低维空间按
密度层次寻找不规则簇，并允许一部分样本标为噪声。它比 KMeans 更适合非球形、不同
密度的语义群，但训练成本和跨期漂移风险更高。

实现合同：

```text
train PCA -> UMAP(n_components=8, n_neighbors=30,
                  min_dist=0.1, metric=cosine)
-> HDBSCAN(min_cluster_size=50, min_samples=10,
           prediction_data=True)
-> cluster feature / membership + PCA feature -> Ridge
```

PCA、UMAP 和 HDBSCAN 都只在训练期拟合，验证/测试使用 transform/approximate_predict。
BGE-M3 masked“亏损”的一次同输入复核将股票日多空从 15.26bp 提至 20.35bp，多头从
1.50bp 提至 6.17bp，8/9 年为正；但跨 prompt 增量不稳定，也未超过最强软聚类组合。

### 8.5 GMM

Gaussian Mixture Model 假设 PCA 表示来自 k 个多元高斯成分，使用后验概率而不是最近
质心作为软簇权重。它能表达不同协方差和重叠簇，但高维协方差估计容易不稳定。

Qwen 聚类分析已做 k=3/5/8 的 GMM 年度收益热图和簇收益汇总。当前用途是结构描述和
稳健性，不作为公平比较的主收益模型，也不根据全样本热图选择 k。

### 8.6 聚类验收边界

- ARI：不同 seed/年份簇划分的一致性；
- silhouette：簇内紧密和簇间分离；
- cluster size/noise share：检查退化簇；
- 簇收益排序：检查训练到验证/测试是否保持方向。

这些指标只描述表示空间，不能选择收益模型。聚类“有效”必须在同新闻、同 PCA、同测试
日的 OOS RankIC、成本后组合或风险指标上超过基线，并有跨年稳定性。

## 11. 三模型公平比较合同

### 11.1 表示

- RoBERTa/BGE token：`prompt_token_embeddings` 的精确目标 span 均值；
- RoBERTa/BGE body：`body_mean`；
- Qwen token：目标 span 均值，排除句号；
- Qwen body：`article_mean`；
- 不使用 `full_mean` 冒充正文；
- 每模型单独 PCA，但使用同 PCA32 算法和同训练窗。

`prompt_token_embeddings.npy` 的 `N × P × D` 依次表示新闻/公告数、Prompt token 位置数、
模型 hidden size，不是一个乘法指标。目标 span 在 `P` 中选定对应位置并求均值，得到
`N × D`；`prompt_mean` 则对全部 Prompt 位置求均值。RoBERTa/BGE-M3/Qwen 的 `D` 分别
为 768/1,024/4,096，`P` 由各自 tokenizer 和 Prompt 决定。

### 11.2 固定参数

```text
PCA                 randomized 32, random_state=42
Ridge               alpha=100
MiniBatchKMeans     k=6
KMeans seeds        17, 29, 42, 71, 113（历史稳定性；主配置固定）
soft KMeans         temperature=0.5, shrinkage=500
UMAP                 8D, neighbors=30, min_dist=0.1, cosine
HDBSCAN              min_cluster_size=50, min_samples=10
```

### 11.3 因子与融合

基础 OOS 因子共 24 个：3 模型 x 4 prompt x 2 表示。融合分为：

- 单模型四 token；
- 单 prompt 三模型；
- 12 token、12 body 和全部 24 因子；
- 逐日横截面标准化后比较等权、Ridge、ElasticNet、HistGradientBoosting。

融合器只能使用历史 OOS 基础预测训练，测试年权重冻结。树模型不能直接在全样本 raw
embedding 上训练，也不能把一级测试预测返回去调参。

### 11.4 用户假设的判定

只有同时出现以下证据，才支持“Qwen 兼顾共同语义和细微差别并产生增量”：

1. RoBERTa centered cosine 显著低于 BGE-M3；
2. BGE-M3 跨 prompt 因子相关和 Top20 重合最高；
3. Qwen 几何接近 BGE-M3，但因子相关低于 BGE-M3；
4. Qwen 四 token 融合超过 Qwen 最佳单 token 和正文；
5. 融合增量至少三分之二测试年为正，日期 bootstrap CI 不跨 0；
6. 三模型融合继续超过最佳单模型。

若 Qwen 只有高 embedding 相似度而融合无增量，结论只能是“表示更平滑”；若 token
不能稳定超过 body，只能写“部分 token 在聚类或尾部排序提供增量”。

## 14. 已知风险

1. 新浪、巨潮和旧新浪面板 row_index 不同，静默 join 会产生严重错配。
2. BGE 中性 embedding 是 partial，不能与完整 RoBERTa 做全量样本比较。
3. 巨潮虽覆盖 2010--2026，Qwen/四 prompt 最小交集和测试年可能更短，必须报实际交集。
4. Qwen 后置 prompt 与双向 encoder 的前置 prompt 结构不同，不能把坐标相似度当同构。
5. `simple_states` 部分历史记录有 ErrorCode=1002，异常 `RetTN/SharpeTN` 不可信。
6. 新浪标签与平台收益曾有定义差异，同池超额和全市场收益不可横比。
7. 聚类图、ARI 和 silhouette 不能替代监督样本外增量。
8. 估值绝对水平跨股票不可比，应使用股票自身滞后 log 基准或行业调整。
9. 高频标签覆盖较短时可以砍掉早期新闻，但训练/测试协议必须随实际覆盖重新声明。
10. 新浪联网采集只能在本地；集群运行采集违反当前项目约束。
11. 任务提交后 runner 使用工作区实时代码；修改核心脚本前应核对提交快照/哈希。
12. PDF 文献和授权数据不入 Git，只提交清单和哈希。

## 15.1 研究主线一：证明 Prompt 产生不同因子

当前最重要的问题不是哪个 Prompt 的 cosine 更大，而是同一正文在替换目标短语后，是否
产生不同、可重复且有经济增量的样本外因子。已冻结的结构事实是：RoBERTa 四个目标 token
的跨 Prompt Spearman 约 0.653，BGE-M3 约 0.892；对应 `full_mean` 约 0.997/0.972。
目标 span 的差异明显大于宽池化，但这仍然只是表示证据。

下一步必须按三层证据执行：

1. 表示层：每模型、每 Prompt 计算 centered cosine、标准化 L2、CKA、同日因子 Spearman
   和 Top20 重合。PCA32/scaler 只能在训练折拟合，禁止用全样本图或测试集调参。
2. 预测层：每个 Prompt 使用相同 6+2+1 滚动折、相同标签和 PCA32+Ridge，输出逐年 RankIC、
   IR、正年份、月度正 IC 和日期区块 bootstrap 的配对 delta。
3. 经济层：按同一个持仓/平滑/成本执行器计算 Top20 持仓、日均 bp、换手、容量、行业/规模
   暴露，并在市场、行业、规模、动量、反转、beta、历史波动率、流动性和新闻数量残差化
   后复核增量。

必须有 no-prompt、neutral prompt 和同长度无关词安慰剂。若安慰剂也产生同等增量，判为
槽位或长度伪影；若只有表示距离而没有 OOS 或组合增量，只能称为“表示被区分”。四 Prompt
融合超过最佳单 Prompt，且增量至少 6/9 年为正、bootstrap 区间不跨 0，才可升级为不同因子。

## 15.2 研究主线二：解释 RoBERTa、BGE-M3、Qwen 的相关性

原始坐标不可跨模型比较：768、1024、4096 维不同，且 RoBERTa/BGE-M3 是前置 Prompt 的
双向 encoder，Qwen 是后置 Prompt 的 causal embedding。统一比较对象是每个滚动训练折的
PCA32+StandardScaler 后统计量：

- 几何：centered cosine、标准化 L2、linear CKA；
- 因子：逐日横截面 z-score 后的 Spearman、RankIC、Top20 重合；
- 残差：一模型 OOS 预测对另一模型 OOS 预测的残差相关和增量 R²；
- 融合：等权、Ridge、ElasticNet、HistGradientBoosting，权重只在验证期选择。

只有冻结的三模型融合至少 6/9 年超过最佳单模型，且区块 bootstrap 增量不跨 0，才能说
“模型互补”。Qwen 当前只有“收益”单 Prompt 的 token/article 对照，不能外推到四 Prompt。
如果 Qwen 与 BGE-M3 相似但融合无增量，应写成表示平滑而非细粒度有效；RoBERTa 低相关但
融合有效，则应解释为可利用的任务分解，而不是直接判定模型较差。

## 15.3 研究主线三：Regime、全股票和宏观指数新闻

### 波动率

至少同时做下一日实现波动率水平、下一日 `log1p` 变化、5/20 日跳升和 tail/jump 事件。
水平高 RankIC 可能只是股票固有风险，变化和跳升才检验 Regime 转换。需要 1 分钟 OHLCV
和成交量，保留前一日及未来窗口；加入股票/行业/市场波动率控制，并报告风险校准和尾部命中。

### 流动性

使用 1 分钟 bid/ask 或成交价重构买卖价差，分别预测下一日价差水平、价差 log 变化和
成交量/换手冲击。控制流通市值、价格、停牌、涨跌停和成交额。高水平信号必须同时通过
逐股/行业残差化、成本、换手和容量检查，不能只看 RankIC。

### 全股票横截面

建立每日所有合格股票面板，处理上市/退市、停牌、复权、行业、规模和新闻覆盖。无新闻股票
保留为显式 missing/no-news 类别并增加缺失指示变量，不能静默删除。分别比较新闻股票池、
全市场含缺失、全市场有新闻评分三种口径，报告每日覆盖、有效持仓、行业集中度、规模暴露、
换手和成本后 bp。

### 宏观和指数新闻

候选指数包括 CSI 300、CSI 500、CSI 1000、上证综指、深证成指、创业板指及行业指数。需要
指数成分有效期、指数 OHLCV、指数/行业新闻时间戳、正文和来源 hash。第一层按等权、市值权、
新闻数量、稳健中位数和最大冲击聚合成市场新闻因子，预测指数收益、波动率、成交额和 breadth；
第二层把个股新闻对市场因子残差化，预测个股超额收益；第三层加入市场波动率、流动性和成交量
Regime 交互。不能把一条指数新闻复制给全部成分股。

新浪联网采集仍只能在本地执行；巨潮使用可追溯的官方公告页面/PDF。东方财富和雪球只做补充
情绪实验，遵守可见页面、限速、不绕过登录/CAPTCHA 和不调用隐藏 API 的边界。

### 建议执行顺序

1. 完成新浪/巨潮三模型四 Prompt 最小交集和 token/body/no-prompt 同折因子。
2. 先冻结 Prompt 差异、跨模型相关和 late fusion 结论。
3. 再做波动率/价差的水平、变化、跳升及残差化。
4. 建立全股票横截面并审计缺失新闻和容量。
5. 最后接入指数/行业新闻和层级 Regime 交互。
